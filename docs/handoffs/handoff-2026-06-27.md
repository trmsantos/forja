### Context
Forja = AR-collections micro-SaaS: connect Stripe (read-only) → auto-chase overdue invoices with
escalating reminders. This session was operational/debugging: the user added RESEND_API_KEY and a
test Stripe connection, and we drove the verification email + the dry-run collections sweep to
actually work end-to-end. Fixing that uncovered a chain of four latent bugs (each masking the next).

### Built / fixed this session (file-level — all in commit e8d1bc7)
- app/main.py: moved `load_dotenv()` ABOVE the local `.email`/`.security` imports. Those modules
  read env at import time (RESEND_API_KEY, JWT_SECRET, ENCRYPTION_KEY), so loading .env afterward
  left them snapshotting unset values / defaults. Root cause of "key set in .env but ignored".
- app/email.py (`_send_resend`):
  - Verify TLS against certifi's CA bundle. This Python (macOS python.org 3.14) has no OpenSSL
    cert paths → urllib died with CERTIFICATE_VERIFY_FAILED. Falls back to system store.
  - Set a `User-Agent` ("Forja/1.0 …"). Cloudflare in front of Resend blocks the default
    `Python-urllib` UA with HTTP 403 "error code: 1010".
  - Log Resend's response body on HTTPError + the email id on success (the endpoint returns
    {"ok":true} regardless, so failures were previously invisible).
- app/stripe_sync.py: added `_field(obj, key, default)` (subscript + KeyError fallback) and replaced
  all `inv.get(...)` calls. stripe-python v15's StripeObject dropped dict-style `.get()`, so the
  first real invoice sync crashed with "AttributeError: get". Was hidden while sweeps had 0 invoices.
- requirements.txt: declared `certifi` (was only transitive).
- test_collections_agent.py: NEW section 4 — regression test that drives `upsert_invoice` / `_field`
  with a fake object mimicking a v15 StripeObject (no `.get()`), so a future SDK bump can't silently
  rebreak sync. Full suite still passes.
