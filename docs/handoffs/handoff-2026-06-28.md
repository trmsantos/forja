### Built this session (file-level)

**Task 1 — Free overdue-invoice audit (top-of-funnel, no signup)**
- `backend/app/stripe_sync.py`: `audit_summary(api_key)` — reads open invoices IN MEMORY and returns
  outstanding total, open count, overdue count, overdue amount, and the oldest overdue invoice.
  Reuses the `_field()` accessor. **Persists nothing** (no key, no invoices).
- `backend/app/main.py`: public `POST /api/audit` (`AuditIn` model). Validates the key the same way
  as `/api/connect/stripe` (`stripe.Invoice.list(limit=1)`), returns the summary, and optionally
  captures an email as a lead (reuses the `leads` table; best-effort, never blocks the preview).
- `frontend/src/pages/Audit.tsx`: new `/audit` page — key + optional-email form, result stat cards,
  oldest-overdue detail, privacy reassurance, and a "Start chasing these →" CTA to `/signup`.
- `frontend/src/lib/format.ts`: extracted shared `money()` (mirrors the dashboard); `Account.tsx`
  now imports it instead of its local copy.
- `frontend/src/lib/api.ts`: `runAudit()` + `AuditSummary` type.
- `frontend/src/App.tsx`: `/audit` route. `Hero.tsx` + `Nav.tsx` (desktop + mobile): link to it.

### Open decisions / not done
- "Overdue" in the audit = strictly past the due date (`due < now`), which is slightly looser than the
  reminder engine's "≥1 day past due". Intentional (intuitive for a self-serve audit) — revisit if it
  confuses visitors.
- Audit lead capture sends a studio notification but does **not** auto-reply to the visitor (they
  didn't fill a contact form). Confirm that's the desired behavior.
- Recap "recovered this week" relies on `tracked_invoices.updated_at` being bumped when Stripe marks an
  invoice paid (it is, via the sweep's reconciliation). If a paid invoice is never re-synced, it won't
  count — acceptable given the daily sweep.
- Not run live end-to-end against real Stripe (dry-run only). The recap was exercised via dry-run.
